# 实战教训（来自 2026-09-17～20 一次完整跑：约 3,000 万子 agent token、5 个 workflow、130+ agent）

## 方法层
- **先盘人，再盘项目，最后才盘市场。** 路径由「这个人卡在哪一步」决定，不由「哪条路技术上最适合」决定——绝大多数路他都能做。
- **资产卡零收入证据本身就是最重要的发现。** 21 张卡、6 个创业方向、十年，几乎没有一次向真人报过高客单的价：好路径的第一判据变成「哪条路能在 14 天内逼他把一张带金额的报价单发给一个真实的人」。
- **「Day-1 先核实再卖」在别人身上是纪律，在他身上是最体面的延期理由。** 凡是「先做 demo/先建词表/先核接口再报价」的路径一律降权。
- **热启动资产要逐人分类，别信关键词命中数。** 「商业话题密集约 300 人」逐人分类后暖决策者只有 27 人，46% 的高频联系人是向他卖东西的人；对方亲口说过的需求只有 3 条，其余都是分析师的「需求假设」。
- **Top N 常常是同一条阶梯的几档价位，不是三门生意。** 27 个人的井养不起三条互不相干的线。
- **过程指标代替金额指标。** 第 3 个月达标概率只有 3–7% 时，拿金额当 KPI 等于预约一次自我否定；改成「每 4 周 ≥6 份带金额的报价」。
- **红队三路缺一不可。** 需求真伪打掉「行业推断当需求」；成交与交付打掉工时不可加；法律一路打掉一半候选（清单见 SKILL 红线常客）。
- **必须有人专门来推翻主线程的排序。** 反方首席一次改了四处：补第一档价位、预付款从可选改默认、主力降为期权、删第三腿。
- **完整性批评员抓的是视野之外的东西。** 「抄别人」那轮 65 个案例只处置了 23 个就下总体结论、案例全来自卖方侧、上海本地一条都没有——这些主线程自己看不见。

## 我自己的偏差（有方向性，几乎全朝「更乐观」）
- 两条路径共用同一份工时，把各自的红队修正值直接相加 = 同一段销售工时算两遍。**凡是加总，先查是否在抢同一份资源（工时/名单/本金）。**
- 「中性 ¥3–4 万」其实是每周 12 小时的数，被放在每周 8 小时的约束下讲。**凡是区间，先查口径是否与约束一致。**
- 把「开过票」当「付过款」（方向可能相反）。**一句原话能读成两个方向时，两个都写出来。**
- 「72 小时破零仪式」里建议合盘补收款码——法律红队指出撞央行 259 号文与清朗整治。**先查红线再给「破零」建议。**

## 工程层
- 网络不稳时 agent 一律「断点续做」：先查输出文件是否已存在且有 DONE 标记，边做边落盘，并发 ≤5。16 并发 + 卡流一晚烧掉 1,400 万 token 只出 7 张卡。
- 微信数据批次被安全分类器拦下后，不要换精简输入再试（会被判为规避），放弃并如实标注覆盖率。
- 评分表、红队裁决表由脚本从 workflow 结果自动生成，不手抄。
- 第三方姓名只留在本机线索文件，报告与聊天里一律角色化；含姓名的文件标「仅本机」。
- 报告出 PDF：封面/目录/页码 + 用户自己的视觉规范色板；绝对定位元素负偏移会触发 Chrome 整页缩放；宽表格 td 用 overflow-wrap:break-word、code 用 anywhere。
